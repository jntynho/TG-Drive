# TG Drive

تطبيق Android مستقل لتنظيم ملفاتك في **الرسائل المحفوظة في حساب تيليجرام الخاص بك**. مكتوب بـ Kotlin وJetpack Compose، بواجهة عربية وإنجليزية ودعم RTL والوضع الداكن.

**نسخة أولية 0.1.0، وليست خدمة تخزين غير محدود مضمونة أو منتجًا رسميًا من Telegram.**

## المزايا

- ربط حساب تيليجرام موجود: الهاتف، رمز الدخول، والتحقق بخطوتين.
- رفع الملفات كمستندات للحفاظ على محتواها دون ضغط الصور والفيديو.
- مجلدات افتراضية، بحث في جميع الملفات، وفرز بالاسم والحجم والتاريخ.
- إعادة بناء الفهرس من بيانات وصفية مرفقة برسائل الملفات.
- تنزيل إلى وجهة يختارها المستخدم عبر منتقي ملفات Android.
- حذف نهائي مع تأكيد صريح لحذف الرسالة الأصلية أيضًا.
- نقل واحد في كل مرة عبر خدمة أمامية وإشعار.
- فهرس مستقل لكل حساب، وحماية مفتاح قاعدة بيانات TDLib باستخدام Android Keystore.

## البناء والتجربة

المتطلبات: JDK 21، Android SDK platform 36 وbuild-tools 36.0.0، وجهاز Android 8.0/API 26 أو أحدث. Gradle Wrapper موجود بالمشروع مع checksum مثبت.

1. افتح المشروع في Android Studio أو عيّن `ANDROID_HOME` إلى Android SDK.
2. أنشئ تطبيق Telegram من <https://my.telegram.org/apps>.
3. أدخل API ID وAPI hash داخل التطبيق عند التشغيل؛ أو أضفهما في `local.properties` غير المتتبع:

```properties
sdk.dir=/path/to/android-sdk
TELEGRAM_API_ID=your_numeric_app_id
TELEGRAM_API_HASH=your_app_hash
```

هذه بيانات تطبيق Telegram، وليست bot token. لا تضع رموز تسجيل الدخول أو كلمة مرور حسابك أو ملفات الجلسة في المستودع. بيانات API المضمنة في APK قابلة للاستخراج؛ إعداد GitHub Secrets يمنع إدراجها في الكود فقط.

```bash
./gradlew testDebugUnitTest lintDebug assembleDebug
./gradlew connectedDebugAndroidTest  # جهاز/محاكي متصل باللغة الإنجليزية
```

APK التجربة: `app/build/outputs/apk/debug/app-debug.apk`.

## بناء Release

ملف [.github/workflows/release.yml](.github/workflows/release.yml) يبني APK وAAB وخرائط R8 وchecksums. يمكن تشغيله يدويًا من Actions. عند دفع tag مثل `v0.1.0`، يشترط توقيعًا حقيقيًا ثم ينشئ GitHub prerelease. لا يرفع إلى Google Play.

لإنشاء APK قابل للتثبيت بنوع release، أضف أسرار توقيع Android أولًا. البناء اليدوي دون مفاتيح يخرج **ملفات غير موقعة وغير قابلة للتثبيت**، ولا يستخدم مفتاح debug بديلًا.

التفاصيل في [docs/RELEASING.md](docs/RELEASING.md).

## حدود النسخة الحالية

- لا توجد إضافة لتشفير الملفات من طرف إلى طرف. Telegram Saved Messages تخزين سحابي وليس Secret Chat.
- يعرض التطبيق المستندات التي رفعها TG Drive فقط؛ لا يستورد كل رسائلك الشخصية.
- حذف الرسائل الأصلية أو تعديل بياناتها الوصفية خارج التطبيق قد يفقد الوصول أو التنظيم.
- يُستعاد تنظيم المجلدات التي تحتوي ملفات من الرسائل. المجلدات الفارغة محلية فقط.
- لا توجد مزامنة خلفية دورية؛ افتح التطبيق وحدّث الفهرس لرؤية تغييرات الأجهزة الأخرى.
- قد يوقف Android خدمة النقل أو العملية. أعد فتح التطبيق وانتظر تيليجرام وحدّث الفهرس قبل إعادة الرفع لتجنب التكرار. مصادر الرفع غير المكتمل تبقى في مساحة التطبيق الخاصة لتسمح لـ TDLib باستكمالها؛ لا توجد إدارة تنظيف لهذه المصادر في هذه النسخة.
- لا يوجد نسخ تلقائي للصور، أو مشاركة عامة، أو معاينة داخلية، أو قفل بالبصمة، أو سلة محذوفات، أو تقسيم ملفات كبيرة.
- بعض خطوات الدخول الإضافية مثل تسجيل حساب جديد والتحقق عبر البريد غير مدعومة. يلزم حساب موجود، ويمكن أن تفرض Telegram إجراءات أخرى.
- تطبق حدود Telegram والحساب الفعلية؛ لا نحاول تجاوزها.

## الجودة والأمان

اختبارات الوحدة تغطي وصف الملفات العربية، رفض المسارات الخبيثة، البحث والفرز، استعادة الفهرس وعزل الحسابات. اختبارات الجهاز تغطي تحميل TDLib الحقيقي، شاشة الإعداد، وتأكيد الحذف. اختبارات الجهاز لا تُسجل الدخول إلى Telegram ولا تثبت نجاح النقل عبر الشبكة.

قبل اعتبار التطبيق صالحًا لملفات مهمة، نفّذ قائمة [docs/TESTING.md](docs/TESTING.md) بحساب اختبار وراجع [docs/SECURITY.md](docs/SECURITY.md). راجع أيضًا شروط Telegram API ومتطلبات Google Play الحالية قبل التوزيع العام.

## تنظيم المشروع

- `data/TelegramDrive.kt`: جلسة Telegram والمصادقة والفهرسة والنقل.
- `data/FileMetadata.kt` (داخل `DriveFile.kt`): صيغة وصف الملفات والفرز.
- `data/IndexStore.kt`: فهرس محلي ذري لكل حساب.
- `data/SecureSettings.kt`: حماية مفاتيح محلية باستخدام Keystore.
- `ui/`: واجهات Compose.
- `TransferService.kt`: نقل يبدأه المستخدم في خدمة Android أمامية.
- `.github/workflows/`: الفحوص والإصدارات.

Each cloud task already has an isolated checkout. Use this checkout; do not create Git worktrees unless explicitly requested.
