# مراجعة واجهات TG Drive — الإصدار 0.5

أُجريت هذه المراجعة قبل تنفيذ التعديلات، اعتمادًا على شيفرة الواجهات وعارض الوسائط ومراحل الرفع والمعاينات المرسومة. التقرير الإنجليزي المفصّل: [UI-AUDIT.md](UI-AUDIT.md). هذه قائمة بالمشاكل المكتشفة ضمن هذا النطاق؛ الفحص على هاتف وحساب حقيقيين يظل ضروريًا لاكتشاف مشاكل الأجهزة والترميزات.

| المشكلة | أثرها | المعالجة |
|---|---|---|
| رأس ثابت يحمل TG Drive في كل الصفحات | لا يوضح موقع المستخدم | عنوان يتبع الصفحة، مع رجوع عند الحاجة |
| ازدحام الرأس بالتحديث واسم الحساب | تشتيت ومساحة ضائعة | دائرة لصورة Telegram، تفتح إدارة الحسابات؛ المزامنة ضمن خيارات المكتبة |
| تكرار الرأس داخل صفحات الإعدادات وHome | هرمية غير واضحة | رأس واحد مشترك، مع الاحتفاظ بالنص الترحيبي المطلوب في Home |
| زر الرجوع في صفحة الملفات لا يطابق رجوع Android | التنقل إلى مكان مختلف | رجوع للمجلد الأب، ثم Home |
| الرجوع من الخزائن يتجاوز صفحة الخصوصية | ضياع سياق التنقل | العودة للخصوصية أولًا |
| بطاقات المعرض مستديرة ومليئة بالأسماء والقوائم | تشويش بصري ونقرات خاطئة | صور 4:5 بلا انحناء ولا أسماء ولا قوائم فوقها |
| حذف الاسم بصريًا قد يضر قارئ الشاشة | صعوبة تمييز الصور | بقاء الاسم كتسمية وصول دون عرضه على الصورة |
| القائمة غير متوفرة داخل العارض | فقدان خيارات الملفات بعد تبسيط المعرض | قائمة داخل عارض الصورة والفيديو، بكل الخيارات الحالية |
| تكبير الصورة يسمح بسحبها خارج الشاشة | فراغ بدل الصورة | تحديد السحب بحسب نسبة الصورة وحجم الشاشة |
| لا يوجد عرض غامر للصورة | استهلاك مساحة بالصورة | إخفاء وإظهار الأدوات، ملء الشاشة، تكبير بإصبعين ونقر مزدوج |
| عارض الفيديو يتصل بمشغّل مشترك قد يحمل ملفًا سابقًا | فيديو أو صوت خاطئ | مشغّل خاص بالفيديو المفتوح، يُحرر عند إغلاقه |
| الفيديو محصور في مساحة 16:9 ثابتة | عرض سيئ للفيديو العمودي | ملاءمة الفيديو للمساحة دون تشويه أو فرض نسبة |
| الحاجة لضغطة تشغيل إضافية | تجربة بطيئة | بدء تشغيل الوسيط المختار، مع أدوات التشغيل الأصلية |
| غياب مسار واضح لخطأ التشغيل | شاشة تحميل عالقة | رسالة ومحاولة جديدة؛ خيارات الحفظ والفتح الخارجي باقية |
| استمرار الفيديو عند ترك الصفحة | صوت أو استهلاك غير متوقع | إيقاف مؤقت عند مغادرة الواجهة، وتحرير المشغل عند إغلاقها |
| بعض الأزرار الأفقية لا تتسع مع الخط الكبير | قصّ عناصر التحكم | لفّ الأزرار وتقييد العناوين وتمرير النصوص الطويلة |
| تسميات مربعات الموافقة لا تستجيب للنقر | هدف لمس صغير | صف واحد قابل للنقر مع وصف واضح لقارئ الشاشة |
| اختلاف وزن وأشكال الأيقونات | هوية غير موحدة | مجموعة Lucide موحدة بأطراف مستديرة |
| أيقونة التطبيق عامة ولا تطابق الواجهة | ضعف التميّز | تصميم Folded Cloud بصيغة SVG وموارد Android متكيفة |
| انتظار Telegram يظهر كأخطاء متكررة على الملفات | شعور بتعطّل الرفع | عدّ تنازلي للحساب مع حفظ الطابور والاستئناف |
| المحتوى المرفوع قد يبدو فاشلًا بسبب الفهرسة | عدم وضوح ما اكتمل | مرحلة «Saving library information» مستقلة عن إرسال المحتوى |
| إعادة قراءة الكاش عند عمليات متكررة | فجوات بين الملفات | صيانة دورية، مع استجابة عاجلة عند نقص المساحة |

## قواعد التصميم

- هدف أساسي واضح لكل شاشة، مع تدرج بصري بسيط.
- استخدام الأزرق للأفعال المهمة، والخلفيات المحايدة للمحتوى.
- أهداف لمس لا تقل عن 48 dp، وأسماء وصول للأزرار والصور.
- إبقاء التحذيرات المتعلقة بالحذف والتصدير والتشفير عند القرار المناسب.
- حركة أفقية قصيرة، مع احترام إعداد مدة الحركة في Android.
- الاحتفاظ بمنتقي الملفات والتحقق البيومتري وأدوات التشغيل الأصلية للنظام.

## ما يحتاج تجربة فعلية

تحديث صورة Telegram، الأداء مع آلاف الصور، استجابة اللمس على أجهزة مختلفة، الفيديوهات ذات الترميزات المتنوعة وHDR، الخط الكبير وTalkBack، حدود إرسال Telegram الفعلية، والتحديث على هاتف المستخدم. الاختبارات الاصطناعية لا تعادل هذه التجارب.
